# B站缓存合并器 (BiliCacheMerge)

[English](README.en.md)

把 **PiliPlus** 的离线缓存（`video.m4s` + `audio.m4s`）无损拼成 MP4，并把缓存里的 `cover.jpg` 写进 MP4 作为封面。

- **不重新编码**（`ffmpeg -c copy`）：1.3 GB / 51 分钟的视频约 4 秒完成，画质零损失。
- 只认缓存结构，**自动忽略弹幕**（`danmaku.pb`）。

## 1. 运行

**双击 `BiliCacheMerge.exe`** 即可（无控制台窗口）。

`BiliCacheMerge.exe` 是个很小的启动器：它会找你机器上的 Python 并打开界面，
所以 **`.exe` 必须和 `BiliCacheMerge.py` 放在同一个文件夹里**（本目录已经是这样，别把 exe 单独拷走）。
如果安全软件拦了这个 exe，直接运行 `python BiliCacheMerge.py` 即可，功能完全一样。

也可以手动运行：

```bat
python BiliCacheMerge.py
```

要求：Windows + Python 3.8 以上（自带 tkinter，实测 3.11 / 3.13 正常）。
ffmpeg 已放在 `bin\ffmpeg.exe`，开箱即用，不需要另装。

> **程序放在哪个文件夹很重要**
>
> 请把整个文件夹放在**普通目录**（例如 `D:\BiliCacheMerge`、`G:\BiliCacheMerge`、`C:\Users\<你>\BiliCacheMerge`）。
> 如果放在带「**低完整性**」安全标签的目录里（某些沙箱 / 代理工具的工作区会这样标），
> 目录里的 `BiliCacheMerge.exe` 会继承该标签，双击后被系统按低完整性启动，症状是：
> **界面能开、缓存能扫，但一合并就报 `Permission denied` / `输出目录不可写`，而且只有程序所在目录能写**。
>
> 遇到这种情况，两个办法：
> 1. 把整个文件夹换到普通目录（推荐）；
> 2. 或者双击同目录的 `启动.vbs`（无窗口）／`调试启动.bat`（带黑窗口），这两个不经过 exe，不会被降权。
>
> 判断方法：程序标题下方如果出现**黄色提示条**，就是正在受限环境里运行。

## 2. 使用步骤

| 步骤 | 操作 |
| --- | --- |
| 1 | **输入地址**：指向 PiliPlus 的缓存根目录。**强烈建议先在 PiliPlus 里把缓存路径改到数据盘**（设置 → 其他设置 → 缓存路径），再用这个目录当输入地址，见第 5 节；先不改也行，默认位置是 `C:\Users\<你>\AppData\Roaming\com.example\piliplus\download`（选 `download` 这一层，或直接选某个视频文件夹）。**不知道缓存在哪？看第 5 节「怎么找到缓存目录」** |
| 2 | **输出地址**：MP4 存放位置，可点「浏览…」或「打开目录」 |
| 3 | 点 **扫描**，列表会显示每个缓存的封面缩略图 + 将生成的文件名 + 时长/分辨率/画质/大小/缓存日期/状态 |
| 4 | 勾选要合并的条目（支持 全选 / 全不选 / 反选 / 只选未合并，Ctrl+A 全选） |
| 5 | 点 **合并选中**，进度条与状态栏显示进度；完成后条目变为「已合并」 |
| 6 | 需要腾空间时点 **删除已合并的原文件** —— 勾选「我知道我在干什么」并等 5 秒倒计时，才会真正删除（MP4 不受影响，删完要重启 PiliPlus，见第 5 节） |

> 第一次打开（或路径为空）时，输入 / 输出这两栏里会显示一段**浅灰色示例提示**，
> 点进去输入、或点「浏览…」选好目录后提示就消失；有内容时不会再出现。

工具栏右侧可以按 **名称 / 时间 / 大小 / 时长 / 状态** 排序（「时间」按缓存下载时间从新到旧），
也可以只看「未合并」或「已合并」。

合并结束后**不会**自动弹出资源管理器（默认关闭）。想让它合并完自动打开输出目录，
到 **设置** 里勾选「合并完成后自动打开输出目录」即可；即使打开失败也只写日志，不会弹错误框。

小技巧：**双击列表条目**可以打开已合并的 MP4，未合并时直接打开对应的缓存文件夹。

## 3. 命名规则

```
合集名（如果有）-标题-作者-av/bv号
```

| 情况 | 结果 |
| --- | --- |
| 普通视频 | `【东方动画】热情高唱～芙兰朵露和她的小fumo-幻想乡的新月-BV13ZbT6UEo5.mp4` |
| 合集里的视频 | `游戏内外完全解析-《恶魔之魂》-炮火编辑部-BV1BAfoY5EvF.mp4` |
| 没有 BV 号 | 用 `av` + avid 代替 |
| 多 P 视频 | 同标题不同分P时自动用 `P1/P2…` 区分 |

文件名会自动过滤 Windows 非法字符（`\ / : * ? " < > |`），过长时截断标题并保留作者与编号。

## 4. 封面 / 缩略图

合并时会把 `cover.jpg` 作为 **MP4 `covr` 封面**写入（`-disposition:v:1 attached_pic`），
同时写入 `title / artist / album / comment` 元数据（`album` = 合集名）。

- **支持的播放器与媒体库**（Kodi、Plex、Emby、iTunes、部分手机相册、部分播放器皮肤）会直接显示这张封面。
- **Windows 资源管理器**对**视频文件**的缩略图是系统解码首帧生成的，不会读取内嵌封面（这是系统行为，与写入方式无关）。
  如果希望在文件夹里也能看到封面，请在 **设置** 里勾选「同时在输出目录保存同名 cover.jpg」。
- 不需要封面时可在 **设置** 里关闭「把 cover.jpg 写入 MP4 封面」。

列表里的缩略图是程序用 ffmpeg 把 `cover.jpg` 缩小后缓存在 `thumbs\` 里；
万一取图失败会用「标题首字 + 色块」占位，具体原因会写进「显示日志」。

## 5. PiliPlus 缓存结构（程序识别依据）

```
<缓存根>/
└── 117230125849363/            avid
    └── c_41670543354/          cid（一个分P）
        ├── entry.json          标题 / 作者 / BV号 / 合集 / 时长 / 分辨率
        ├── cover.jpg           封面
        ├── danmaku.pb          弹幕（忽略，不读不删）
        └── 120/                画质目录
            ├── video.m4s
            ├── audio.m4s
            └── index.json      （忽略）
```

- 递归查找所有包含 `entry.json` 且带 `video.m4s` 的目录；
- 同一分P有多个画质目录时，优先用 `entry.json` 里记录的 `video_quality`，否则取编号最大的；
- `entry.json` 缺失或没有视频流的目录会被跳过。

其他客户端如果只是文件命名不同，识别不到就不会出现在列表里，也不会有任何写操作。

### 强烈建议先把缓存目录改到数据盘

PiliPlus 默认把缓存放在系统盘用户目录里：

```
C:\Users\<你>\AppData\Roaming\com.example\piliplus\download
```

这是隐藏目录，而且视频缓存动辄几十 GB，很容易把 C 盘撑满；重装系统时也最容易被一起清掉。
所以**强烈建议先在 PiliPlus 里改掉缓存路径**：

> **设置 → 其他设置 → 缓存路径**，改到空间充足的数据盘，例如 `D:\PiliPlusCache`

改完之后：

- 本程序的「输入地址」就填这个新目录（例如 `D:\PiliPlusCache`）；
- 合并输出的 MP4 也建议放同一个盘，省得跨盘搬来搬去；
- 注意：PiliPlus **不会迁移**已经缓存好的旧文件，旧缓存还留在原位置，
  需要的话手动搬过去，或者在新目录里重新缓存。

### 怎么找到缓存目录

不用自己去翻 `AppData`，在 PiliPlus 里就能直接定位：

> **我的 → 离线缓存 → 点这个视频右下角的「⋮」→ 打开本地文件夹**

打开的就是该视频的缓存目录（`…\<缓存路径>\<avid>\c_<cid>`），
把它的上一级（也就是你在设置里指定的那个缓存路径）填进程序的「输入地址」即可
（直接填这个视频目录也能扫到）。

### 删完缓存要重启 PiliPlus

用「删除已合并的原文件」清掉缓存后，**PiliPlus 的离线缓存列表不会立刻更新**：
列表里可能还留着那几条，点开却播放不了。**把 PiliPlus 完全退出再重新打开**，列表才会刷新。

`bin\ffmpeg.exe` 为 ffmpeg 7.1（essentials build，静态编译，无需额外 DLL）。

查找顺序：**设置里的路径 → `bin\ffmpeg.exe` → 程序目录 → 系统 PATH → 常见安装位置**。

## 8. 删除与安全

「删除已合并的原文件」是**不可恢复**操作，因此做了四道闸：

1. 只处理状态为「已合并」的条目；
2. 弹出确认框，列出**所有**将被删除的目录与总大小；
3. 必须手动勾选「**我知道我在干什么**（上述缓存将被永久删除，且无法恢复）」；
4. 勾选之后还要**等 5 秒倒计时结束**，删除按钮才会亮起来（中途取消勾选会重新计时）。

另外，程序只删除**输入目录内**、名字以 `c_` 开头、且确实包含 `entry.json` 的目录，
并顺带清理因此变空的 avid 目录。输出目录里的 MP4 永远不会被这个按钮动到；
平时的合并对缓存是只读的。

**觉得 5 秒等待太啰嗦？** 到 **设置** 里取消勾选「删除原文件前等待 5 秒」，
之后勾选「我知道我在干什么」就能立即删除（那一行的勾选依然是必填的）。

> **删完记得重启 PiliPlus**：它不会监测缓存目录的变化，离线缓存列表要重启（完全退出再打开）才会刷新。

## 9. 常见问题

**扫描不到视频？**
确认选的是 PiliPlus 的缓存目录：输入地址要选到 `download` 这一层或更上层，
也可以直接选某个视频文件夹（如 `117230125849363`）。
找不到的话，在 PiliPlus 里「我的 → 离线缓存 → 视频右下角「⋮」→ 打开本地文件夹」直接定位。

**合并后的时长比缓存里标的少一点点？**
正常。`entry.json` 里的时长是向上取整的，实际文件时长会略短（一般 1 秒内）。

**删掉的缓存，PiliPlus 里怎么还显示？**
PiliPlus 不会实时监测缓存目录。把它**完全退出再重新打开**，离线缓存列表才会刷新。

**4K / HEVC 视频打不开？**
这是播放器缺解码器，不是合并问题。Windows 自带播放器可能需要装 HEVC 扩展，或用 PotPlayer / VLC。

**合并失败怎么办？**
点「显示日志」查看 ffmpeg 的具体报错；常见原因是缓存没下载完（`is_completed=false`）或磁盘空间不足。

**提示「以受限方式启动 / 低完整性令牌 / 继承了 DSH 沙箱」？**
说明这个窗口是在受限环境里启动的（进程令牌是**低完整性**）：
低完整性进程写不了中完整性的普通目录，除程序所在目录外，写其他盘符 / C 盘都会被拒绝。
这跟文件夹权限、ACL、安全软件都无关。**关掉这个窗口，用别的方式自己启动**：

- Win+R，输入完整路径回车，例如 `F:\VSC\BiliCacheMerge\BiliCacheMerge.exe`；
- 或在资源管理器地址栏输入程序文件夹路径，再双击 `BiliCacheMerge.exe`。

不要从聊天/网页里的文件卡片点开（那类"由别的程序代开"的方式会继承对方的限制）。
程序启动后如果标题下方没有黄色提示条，就说明拿到了正常令牌，可以写任意目录。

**报错 `Permission denied` / `Error opening output file`？**
ffmpeg 被安全软件拦住了写入。国内常见的是火绒 / 360 的「重要文件保护」「文档保护」，
以及 Windows 自带的「受控文件夹访问」——`视频 / 文档 / 桌面 / 图片` 这些文件夹默认受保护。
两种解决办法：

1. 换一个普通目录，例如 `D:\B站视频`（推荐，最快）；
2. 把本程序自带的 `bin\ffmpeg.exe` 加进安全软件的信任区 / 允许列表。

程序在合并前会先试写一个临时文件检测输出目录；不可写时会给出提示并允许你重新选目录，
所以不会出现“点了合并才发现写不进去”的情况。
